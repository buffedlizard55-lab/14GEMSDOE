Find the faults nobody has mapped yet.

The GEMS Prize (US DOE Office of Geothermal) pays for algorithms that surface geological faults missing from the public USGS/INGENIOUS catalogue — faults that indicate geothermal resources in the GeoDAWN region of Nevada and eastern California. Score: a distance-weighted Tversky index that punishes missed faults four times harder than false alarms. Competition closes Dec 3, 2026 23:59 UTC; prize pool $300,000 (verified on the official page — see Data & sources).

2026-09-29 — the site could not produce a submission file. Fixed, and now covered by a test.

What was wrong. docs/js/site.js assigned tifBytesNan without declaring it. The file is a strict-mode IIFE, so the assignment threw ReferenceError: tifBytesNan is not defined inside the promise chain; .catch() swallowed it and every download button stayed disabled. The page reached FAILED: tifBytesNan is not defined and offered no file — exactly the reported symptom. The Python suite could not see it, because nothing in the suite executed the site's JavaScript.

Reproduced, not guessed. node scripts/check_site_build.mjs now runs the real payload.js, tif_writer.js and site.js under a DOM shim. Against the unfixed file it prints buildState = "FAILED: tifBytesNan is not defined" and none enabled. Against the fixed file it prints verdict: PASS (15/15 steps).

Three fixes, not one.

  1. tifBytesNan is declared, and the optional NaN-nodata variant is built in its own guarded function — a failure in the optional variant can no longer block the required file.
  2. The built file is now deflate-compressed in the browser, so the download is ~107 KB instead of ~47 MB and matches the container shape the Python pipeline writes (rasterio compress="deflate").
  3. A finished .tif now ships in docs/downloads/ and is linked from the top of this page, so a visitor with JavaScript disabled — or with a browser that cannot run the builder — still has a file to submit. This is the pattern the sibling team sites use.

Covered by tests/test_site_build.py (15 tests) in both routes: the browser build is read back with rasterio and compared to the shipped payload bit-for-bit, and both files must pass gems.raster.check_submission — the same gate that refuses a file the form would reject with "Predicted values must be in range [0, 1]". Incident recorded as FLAG #14 in research/limitations_and_next.md.

Round 7 — the problem statement told us where the truth is (2026-09-29)

Two official statements reframe the hidden truth: C28 — "portions of the existing fault data may be misaligned from the true location of the surface fault, which is the prediction target" — and C21 — continuations past mapped tips and splays are scoring truth. No R1–R6 arm models misregistration or buried continuation. Five candidates pre-registered (round-7 page): R7-1 expression-aligned traces (misregistration correction, validated via a new --misreg-px stress protocol), R7-2 buried continuation stitching, R7-3 gravity-gradient termination/intersection topology (the label producers' own basin playbook — KB S11 — re-tested on real data after a synthetic-only kill), R7-4 strain-budget deficit, R7-5 transtensional coupling. R7-3/R7-5/R7-1 operators implemented with 20 unit tests; gated this session: R7-1, R7-2, R7-3, R7-5 PROMOTED (far 4/4 each; R7-1 also wins the δ=2 stress 4/4; R7-2's bridge lifts the isolated subset +19 %), R7-4 killed by the prior. Three ensemble attempts (all6, horse7 v1, horse7 v2 at 0.0721/0.0224/0.0075 — far nearly double horse) all fail the fold-wise sparse rule (2/4 each) — the horse arm keeps the weekly slot, at the official-marginal-economics budget (q 0.0225; TEST dense 0.0699).

Round 2 — the blocked holdout has already decided (2026-09-28)

Nine feature arms, one model, one spatially-blocked holdout (scripts/validate_round2.py). No submission slot was spent. Two outcomes matter:

Winner
classifier × (1 + 0.5·geophysics)
+0.0979 combined holdout DTI over the baseline, and the only blend form that improves both recovery (0.3073 → 0.3673) and discovery (0.0081 → 0.0612, 7.5×). Additive and max blends smear probability mass and pay false positives without lifting the per-truth-pixel maximum.
Killed by the gate
gravity-gradient edge terminations
the literature-ranked top candidate — a verbatim statement from the INGENIOUS authors that gravity-gradient terminations defined fault tips and crossings — still made the holdout worse (−0.0059). This is the gate doing its job: an idea with the best published support and the lowest cost was rejected on evidence.

The structural insight behind both results: the baseline is a catalogue-trained model, so its discovery DTI is 0.0081 — it has never been shown a fault absent from the catalogue, and the prize scores only off-catalogue faults (known-fault pixels are masked, forum 11516). The round-1 moves (distinct ideas, not the same idea re-dressed)

Move 1 · structural completion
relay ramps & tips
emit the small connecting faults the catalogue omits at step-overs, horsetails and intersections (Faulds et al.: 32% / 22% / 22% / 8% of systems)
Move 2 · hydrothermal expression
heat · springs · sinter
faults feed hot springs and sinter deposits; where expression exists without a catalogue fault, an unmapped structure is the explanation
Move 3 · magnetic lineaments
edge transforms
structure-tensor / edge detection on the GeoDAWN magnetics for concealed faults with no surface scarp
Move 4 · completeness residuals
strain vs. catalogue
where strain rate and relief predict deformation the catalogue does not show, flag the gap
Move 5 · hide-and-recover
no leaky training
the model only ever learns to recover hidden traces; “distance to known fault = 0” is never the answer

Each move names its layers, its physical signature, and its evidence on the round-1 hypotheses page, ranked by expected DTI gain and implementation cost, with the free official data source that backs it. The five round-2 moves — gravity-gradient edge terminations, seismicity lineaments, alteration-cap margins, 1 m lidar scarps with a paleo-shoreline mask, and range-front topographic steps — are on the round-2 hypotheses page.
