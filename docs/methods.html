Methods — what runs, in what order, and how it is proven

The pipeline is deliberately small-auditable: every stage is a script, every quantity is recomputable from files in data/, and the test suite pins the metric and the format gate to the official equations and requirements. 51/51 tests pass; the synthetic end-to-end demo runs the whole chain without the login-gated data.

Hide-and-recover in one paragraph

Each epoch hides a random fraction of whole connected traces (components, not pixels — pixel-hiding leaves distance-zero leakage), rebuilds all context features from the visible remainder, trains against the full catalogue, and scores DTI on the hidden traces only. The invariant assert_no_leak fails any epoch where a hidden pixel touches the context. Model selection uses hidden-recovery DTI; slot decisions use the spatially-blocked variant with a purge buffer across block edges. The model currently implemented is per-pixel logistic regression (dependency-light, runs anywhere); the reference U-Net is the drop-in upgrade once GPU + the real 418 MB feature stack are present — the protocol does not change.

The round-2 holdout protocol (what the gate actually measures)

Three targets, because staff declined to disclose the data sources, fault types or coverage behind the hidden test faults (forum 11527):

  • recovery — catalogue traces held out of the visible context. The standard hide-and-recover proxy; biased toward faults with a surface expression, because that is how catalogue traces were found.
  • discovery — blind_traces: faults present in the synthetic geophysics but absent from the catalogue by construction (≥ 22 px from every catalogue trace) and never used as training labels. This is the local analogue of the private test set, which staff confirmed is “any fault pixel not already captured by USGS/INGENIOUS” (forum 11536).
  • combined — the union: the best available guess at the population the prize scores, and therefore the gate metric.

The synthetic generator was extended for this: it now produces an explicit catalogue population and a separate true-fault population, and builds gravity / seismicity / conductance / magnetic-low analogues from the true network. That is what makes the discovery target measurable at all — a generator whose geophysics only knew about the catalogue would make the discovery test vacuous.

Honest limitations of the current implementation

  • Feature approximations: trace endpoints are terminal pixels of 1-px-wide rasterized polylines; local strike comes from a neighbourhood inertia tensor. Both have measured error on synthetic geometry (tests) but have not been measured against the real vector labels yet.
  • strike_field uses box convolutions — fine at 320², needs a tiled path for the full 3,292 × 3,730 grid (noted in code).
  • The site's payload currently ships the synthetic demo field; the real field replaces it with one command after a real run.
  • No GPU training yet — logistic baseline only. U-Net port pending data + GPU.
  • Round-2 numbers are from the synthetic forward model, not from the competition rasters (which sit behind a DrivenData login — the data tab redirects to /accounts/login/, verified). They validate the machinery, the sign and rough magnitude of each arm's effect, and that the gate refuses bad ideas. They do not predict a leaderboard score. scripts/validate_round2.py runs unchanged once data/processed/ exists.
  • Hypothesis N4 (1 m lidar scarps + paleo-shoreline mask) is not yet viable: no free official paleo-shoreline dataset has been sourced (irregularity #1b). It is recorded as blocked, not as progress.
